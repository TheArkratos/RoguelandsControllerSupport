# First-A storage drop probe

Run `dotnet run --project tests/storage_first_press_repro/StorageFirstPressRepro.csproj -p:UseSharedCompilation=false` from the repo root. This builds the actual `ControllerMenuSelection` and `ControllerFrontEndMenus` wrappers, uses a stale physical cursor over a level drop zone, and performs exactly one raw A press with no physical mouse click. The in-memory dispatch reproduces the relevant `GameScript.Update` structure: line 5404 enters on a left click, line 5406 raycasts once, layer 16 selects a slot, and the mutually exclusive layer-17 branch at lines 5955–5962 drops a held item. It does not reproduce the entire Unity player loop, unrelated patches, or actual item persistence.

A failure means first A did not exclusively select the intended inventory slot; a pass rules out this particular same-dispatch select-then-drop mechanism, **not** the user's observed drop. Do not use a simultaneous mouse click or a second A press as a substitute for this scenario.
